## 历史案例

### 案例 1
- **日期**: 2026-06-04_134037
- **来源 PR**: feat: 增加从token获取userId的便捷方法22222245a
- **文件**: target/classes/...`:全部 | **来源**: 🤖Agent | **领域**: architecture
- **描述**: PR 中包含了大量 .class 文件的变更（约30个文件），这些是 Java 编译后的二进制产物。将编译产物提交到版本控制是严重的架构实践问题，会导致：1) 仓库体积膨胀，增加克隆和拉取时间；2) 产生大量无意义的 diff，干扰代码审查；3) 不同开发环境可能产生不同的编译结果，导致难以追踪的构建问题；4) 违反了基础设施即代码的原则，构建过程应该可重复且由 CI/CD 管理。
- **修复**: 1) 在 .gitignore 中添加 'target/' 目录；2) 从版本控制中移除所有 .class 文件；3) 确保构建过程通过 Maven/Gradle 等构建工具在 CI/CD 环境中完成，而非提交编译产物。
