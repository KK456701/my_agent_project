- **日期**: 2026-05-19_110427

- **描述**: `is_fraudulent` 函数中的黑名单每 5 分钟同步一次。在这 5 分钟的窗口期内，新被标记为欺诈的用户 ID 不会被检测到，可能导致欺诈交易成功。这是一个典型的因性能优化而牺牲安全时效性的问题。
- **修复**: 1. 使用带有 TTL 的本地缓存（如 `cachetools.TTLCache`）替代全局变量，并设置更短的过期时间（如 30 秒）。2. 引入异步更新机制，在后台持续同步黑名单而不阻塞主请求。3. 对于高风险交易，即使违反 SLA 也应进行实时查询。
